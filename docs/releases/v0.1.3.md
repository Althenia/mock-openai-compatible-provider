# AIPassport v0.1.3

The executable targets
**macOS arm64**, requires separately installed Google Chrome and an authenticated
webchat profile, and remains licensed under **AGPL-3.0-only**.

## Changed

- Added `aipass-browser-provider update`, with optional `--version VERSION` and
  `--install-dir DIRECTORY`. It uses the embedded installer with existing
  checksum verification and atomic replacement, and holds the selected profile
  lock so an active provider/login cannot update concurrently. It does not
  automatically stop or restart the provider.
- Startup instructions are separate webchat submissions: adapter role/protocol,
  then each caller system/developer message in order, then the conversation/task.
  Each startup reply is consumed internally before the next submission. Startup
  replies are not client answers or executable actions.
- Startup is replayed after recovery, compaction, model/variant changes, and
  lost page state. Unchanged bound turns reuse startup while carrying current
  conversation and action schemas. Explicit action-only requests still omit
  caller instructions.
- Request identity includes startup boundaries, model, reasoning variant, and
  compaction state so cached responses cannot skip changed startup context.
- The README provides one first-use route and links to detailed operations and
  runtime documentation. Public documentation output excludes local recordings
  and private diagnostics. GitHub Pages serves the public documentation and
  installer, and the README's `curl` command uses that Pages installer URL.

## Validation boundary

An actual installed YCoding `run --standalone` session using Terra/low delivered
two startup submissions, then a task and read-result continuation. Startup and
first-task payloads matched the projection; the client completed a synthetic file
read and returned its contents, exiting zero. This is one bounded real-client
case, not a reliability guarantee. A repeat after the regression fixes completed
the same read/result/final cycle. Its readable redacted 55.39-second recording played to
the end in Chrome without a media error.

Local checks on 8 September 2026: `bun run typecheck`; unfiltered `bun test`
(485 passed, zero failed); build, isolated-binary, installer, and release-packaging
fixture tests passed. No test or assertion was skipped to obtain that result.
Packaging tests use inert component-source fixtures, not downloaded upstream
archives. The tag-triggered release workflow gates publication on validation,
build, and complete-source archive assembly from committed inputs.

## Known limitations

- Extra startup replies increase latency and consume upstream quota. Separate
  submissions do not create native system-role messages or override site rules,
  and do not guarantee model compliance or improved consistency.
- Beyond that single read cycle, live tools, skills, file operations, MCP,
  every-model reliability, large-context behavior, and billing-accurate usage
  remain unverified. Usage remains estimated and is not a complete upstream bill
  for internal startup replies. Prior [0.1.2 limitations](v0.1.2.md#known-limitations) remain
  unless explicitly revalidated.
- The calling client still owns permissions and tool execution. AIPass does not
  load another application's workspace or agent instructions.
- Responses continuation IDs remain bounded, single-use, and process-local.
  Restarted or expired IDs require authoritative history in a new request.
- Configuration and stored-data schemas are unchanged; no migration is required.

## Installation and rollback

After publication, stop the provider before installing version `0.1.3` with the
[maintained installer](../../site/install.sh) and its `--version 0.1.3` option.
Verify `aipass-browser-provider --version` prints `0.1.3` before restarting.
Once v0.1.3 is installed, use `aipass-browser-provider update` for later releases,
or `update --version VERSION` for a pinned installation. See
[update safety and custom destinations](../operations.md#update-and-restore).
The executable is ad-hoc signed, not Developer ID signed or notarized. Updating
does not restart the service.

To roll back, stop the provider and use `--version 0.1.2`, then restart with the
same configuration and state directories. Do not delete browser credentials or
session state. In-memory Responses IDs do not survive a restart. Rollback also
restores 0.1.2's prompt-delivery behavior and documented limitations.
