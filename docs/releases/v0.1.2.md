# AIPassport v0.1.2

This release fixes the model/Processing selection path exercised by the actual
YCoding smoke test. It does not establish compatibility with every model or
live client-tool workflow. The executable targets **macOS arm64**, requires
separately installed Google Chrome and an authenticated provider profile, and
remains licensed under **AGPL-3.0-only**.

## Changed

- Model selection uses the requested model card, its linked open Processing
  popup, and exact English/Thai labels rather than positional option indexes.
  The requested visible Processing value, picker closure, and composer model
  are verified before prompt submission. Models without Processing use their
  Select/Confirm action without inventing a variant.
- Processing option activation avoids pointer-induced scrolling and keyboard
  focus changes that dismissed or failed to activate the live popup. An already
  selected value is retained rather than toggled off.
- The twenty-model catalog and Processing labels have one TypeScript source of
  truth, with regression checks against the [model matrix](../model-matrix.md).
- The default chat URL requests temporary-chat mode. Existing explicit URL
  configuration remains supported, and temporary-chat state is still verified.
- Release builds use Bun **1.4.2**, with matching runtime source archives and
  regenerated third-party notices. No npm dependency versions are changed.
- Git ignores generated build/release/test artifacts, local browser/session
  state, and OS metadata. These are not release assets.

## Live validation boundary

- Release preparation passed all 467 maintained tests on Bun 1.4.2, typechecking,
  isolated executable checks, installer tests, and release-packaging fixture
  tests. Actual bundled-source checksums and regenerated notices were also
  verified. Packaging fixtures do not replace upstream-source verification.

- Before the version bump, the installed build on Bun 1.4.2 completed one actual
  YCoding conversation through `aipass/GPT-5.6 Terra` with Low Processing. It
  returned exactly `AIPASS_INSTALLED_BUILD_OK`, and YCoding returned to ready.
  Provider evidence recorded a settled assistant message and no
  `browser-turn-failure` diagnostic for that turn.
- A separate direct-webchat run verified six selection steps and three replies
  across Terra Low, Terra High, and Llama 4 Scout, including conversation
  continuity. That run is not evidence of client-tool execution.
- The test provider later reached its host-process lifetime limit. Recorder
  shutdown also failed to finalize its overall summary; the conversation video
  was independently decoded and played successfully. Recordings and raw local
  diagnostics are not distributed.

## Known limitations

- Live tools, every-model chat reliability, Unicode fidelity, large-context
  reliability, provider cache hits, hidden reasoning provenance, and
  billing-accurate usage are not established by the smoke test. Usage remains
  explicitly estimated. Earlier [live-model limitations](v0.1.0.md#known-limitations)
  have not all been revalidated as resolved.
- Browser fixture tests retain their test-local Playwright wake-up timers.
  One preparatory run failed a short-deadline wrong-model fixture; the unchanged
  fixture passed in isolation and in the final full suite. Passing fixtures do
  not eliminate browser timing sensitivity or all upstream timing failures.
- Strict turn-key and offered-action validation remains in place. The browser
  does not itself execute client tools; only the external client can dispatch
  validated actions it offered.
- Responses continuation IDs remain bounded, single-use, and process-local.
  Restarted, consumed, evicted, or oversized history requires a new request with
  authoritative history. No stored-data migration is introduced.

## Installation and rollback

Stop the provider before replacing its executable:

```sh
curl -fsSL https://raw.githubusercontent.com/Althenia/mock-openai-compatible-provider/main/site/install.sh | sh -s -- --version 0.1.2
aipass-browser-provider --version
```

The version command must print `0.1.2`. The installer verifies GitHub's SHA-256
asset metadata before replacement. The executable is ad-hoc signed, not
Developer ID signed or notarized. Installation does not restart the provider.

For offline installation, place the executable beside the complete source
archive, then extract and verify it:

```sh
tar -xzf aipass-browser-provider-0.1.2-complete-source.tar.gz
shasum -a 256 -c checksums.txt
sh install.sh --version 0.1.2 --from-dir .
```

Existing releases are not overwritten. To roll back, stop the provider and use
`--version 0.1.1` with the online installer or that version's verified offline
directory. Preserve state/config directories; process-memory continuation IDs
do not survive the restart. Version 0.1.1 retains its documented selection issue.
