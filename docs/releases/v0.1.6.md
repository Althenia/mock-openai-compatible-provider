# AIPassport v0.1.6

The executable targets **macOS arm64**, requires separately installed Google
Chrome and an authenticated webchat profile, and remains licensed under
**AGPL-3.0-only**. The executable is ad-hoc signed, not notarized.

## Changed

- Provider runtime settings are owned by one selected version-one JSON file.
  Defaults use the validated native macOS account home; `HOME`, XDG variables,
  and former runtime `AIPASS_*` variables do not override those settings.
  Supported explicit CLI options override file values.
- Initialization directly supplies complete caller system/developer instructions
  and every effective offered action schema in one ordered submission. Provider
  action availability remains restricted by the effective per-turn selection.
- One short key-reference envelope-format correction can retry malformed output
  without replaying caller instructions, skill/MCP bodies, history, or schemas.
  Envelope validation requires complete coverage and valid chat payloads, fails
  closed after repeated invalid output, and preserves authorization, safety,
  action authorization, and cancellation behavior.

## Validation boundary

The release candidate passed the unfiltered `bun test`: **648 tests, 0 failures,
and no skips**. Typecheck, build, isolated-binary, installer, and offline release
packaging checks passed before the version bump. Local tests validate provider
transport and prompt projection behavior only; no authenticated webchat run was
performed.

## Known limitations

- Usage remains an estimate, not upstream billing data.
- Browser initialization and a hidden envelope-format correction add latency and
  may consume authenticated provider quota; hidden retry usage remains estimated.
- Synthetic adapters validate local transport and projection behavior only;
  no live-model reliability claim is made.

## Installation and rollback

Stop the provider, then use `aipass-browser-provider update --version 0.1.6` or
the [maintained installer](../../site/install.sh) with `--version 0.1.6`.
Verify `aipass-browser-provider --version` prints `0.1.6` before restarting.
Updating does not restart the service.

To roll back, stop the provider and install `0.1.5`. Review that version's
environment and default-path behavior before restarting; do not assume this
release's file-owned configuration will be reused unchanged. Do not delete
browser credentials or session state.
